Chest BPM 1.6 (11) — automatic Watch control and five-cycle logging
November 14, 2026

Installed
The signed phone build and matching Watch companion are installed. The BPM estimator, feature pipeline and model package still match the frozen 1.5 (7) hashes. These changes improve coordination and data collection; they do not establish better medical accuracy.

Phone-led tests
The phone requests a fresh, trial-scoped Watch session through Apple's HealthKit companion launch API. It sends commands through both immediate and queued WatchConnectivity delivery, retries while waiting for acknowledgement, and waits for three fresh sensor timestamps before a five-second preparation countdown. It requires acknowledgement of the exact Watch stop deadline before beginning a normal recording. The Watch stores and enforces its own deadline; the phone sends a backup stop if it has not seen the Watch stop after a short grace period. Cancelling sends a queued stop immediately.

Unique trial IDs, expiry checks, persisted completed-trial IDs and ordered command phases prevent duplicate or delayed requests from restarting a completed trial or affecting the next wearer. A stop that arrives before its matching prepare is remembered as a cancellation. Wrong-deadline duplicate commands are rejected. The Watch also checks expired deadlines when its sensor callback runs.

Five cycles
Set up five cycles creates 20 steps: five quiet, five background-sound, five brief-repositioning and five off-chest tests. Orders rotate between cycles. Chest tests last about 90 seconds; off-chest tests about 20. Each step needs a ready tap after changing the physical environment. Completion advances the plan; interrupted/failed attempts remain logged and require retry. The saved plan survives app relaunch without silently restarting a microphone. Participant changes end the current plan. Friend consent is still required. Under this user's explicit testing consent, wearer-A series setup enables local raw audio; its toggle can be turned off before any trial.

Logs
Every run remains in Diagnostics/Runs with a manifest recording closed state, rows and bytes. status.json is an atomically replaced small live snapshot. Late reference packets are also retained in a separate phone reference log, and the Watch archives its own readings. Files remain local and backup-excluded. Tools/collect_study.py reads snapshots, fetches closed archives, checks run identities/sequences/counts/bytes and deduplicates retries. Invalid archives are retained for review rather than treated as valid data. The old growing-file reader remains available for historical captures. No new HTTP server, cloud uploader, permanent service or global configuration was introduced.

Mirroring limit
Apple does not provide iPhone camera/microphone access during iPhone Mirroring. Mirroring can therefore control setup and the Watch-only check; real chest recordings require taking over the physical phone. The user does not need to start/stop the Watch manually for each normal trial. Apple permission prompts and an unlocked worn Watch remain prerequisites; user consent cannot bypass those OS requirements.
